# 终端选区拖动时自动滚动

知识笔记 + 已落地行为：按住左键把选区拖到文字区上沿或下沿时，视口跟着滚，选区可以延伸到当前屏幕外面的行。

相关代码：`src/terminal/gpui_emu/view/mod.rs`（`track_selection_pointer`、`selection_scroll_tick`、`selection_scroll_lines`）。  
冻结清单：[HARD_PROBLEMS.md](./HARD_PROBLEMS.md) §A（帧路径上不要空转 `notify`）。

---

## 问题

选区终点以前只按当前可见格子计算。`cell_at` 把行钳在可视区里，拖动过程不改 `display_offset`。指针停在边缘时，操作系统不再发鼠标移动，滚动条不动，屏幕外的历史行选不中。

---

## 别的终端怎么做

指针停住就没有 `mouse_move`，所以要有一件事在按住期间继续滚。

| 实现 | 做法 |
| --- | --- |
| xterm.js（VS Code 终端） | 按下时 `setInterval` 50ms；松开清掉。监听挂在 document 上，终端外面松开也能停 |
| Alacritty | 重复定时器 15ms。指针在文字区外才滚，越出边界越远每次行数越多。回到区内或松开就取消 |
| Zed | **不用定时器**。窗口级 `mouse_move` 里立刻滚，最多 3 行。指针停住不再移动时，这条路径不会继续滚 |

---

## 方案（已采纳）

定时器，加上窗口级鼠标位置。盖住「拖到边缘后停住」；窗口监听盖住「指针已经离开终端控件」。

1. 左键拖动时记下指针（窗口坐标）。
2. 指针进入文字区上沿或下沿（约半行）时，启动**一个**重复任务，间隔 50ms。
3. 每拍按超出距离滚 1～3 行，再用新的 `display_offset` 把选区终点钳到边缘那一行。
4. 指针回到文字中间、左键松开、或开始拖滚动条时，把任务设成 `None`。
5. 选区进行中，在 **paint** 里用 `window.on_mouse_event` 听移动和左键松开。GPUI 这种监听只活一帧，下一帧绘制时清掉，所以要在 `selecting` 为真时每帧登记。

方向与滚轮一致：`Scroll::Delta` 为正是往更老的历史（`display_offset` 变大）；往下拖是负的，朝实时输出底部。

### 明确不做

- 只靠控件上的 `on_mouse_move`（指针停住或离开控件就停）
- 每次移动再 `spawn` 一个任务，或 `detach` 后没有退出条件
- 在任务自己的 `update` 里把 `selection_scroll` 设成 `None`（会在任务还在跑时丢掉它）
- 到顶或到底之后每拍都 `notify`

---

## 资源和重绘

任务存在视图字段 `selection_scroll: Option<Task<()>>` 上。设成 `None` 就取消。视图关掉时字段一起丢掉。

`cx.spawn` 拿到的是弱引用。视图已经没了，`update` 失败，循环退出，不会把 `TerminalView` 留在内存里。

`selection_scroll_live` 用来区分「任务还在等下一拍」和「上一轮已经自己结束、字段里只剩一个跑完的 `Task`」。结束后可以再启动下一次，不会叠多个循环。

每拍先滚动再更新选区，两次终端锁先后拿，不嵌套。视口没变且终点格子和上一拍相同，则不 `notify`。

---

## 松开时

`finish_selection_drag` 只处理一次：窗口监听和控件上的 `on_mouse_up` 都可能进来，`selecting` 已经是 false 就直接返回。

单击（没有拖动）仍清掉选区，避免留下一格假光标。拖过的选区用钳到边缘的格子收尾，再 `include_all`，然后按原行为复制到剪贴板。

选区中途被按键清掉时，下一拍发现 `term.selection` 为空就退出任务。

---

## 验收

- [ ] 回滚很多时，从中间往下拖到最后一行，视口和滚动条跟着走，松手后选区含屏幕外的行
- [ ] 往上拖到第一行，进入更老的历史
- [ ] 指针停在边缘不移动，仍然继续滚；回到文字中间后停止
- [ ] 在终端外面松开，滚动停止，不留下空转重绘
- [ ] 已经到顶或到底时，CPU 不因选区拖动持续升高
